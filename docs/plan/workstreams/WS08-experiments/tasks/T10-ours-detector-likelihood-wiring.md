## Obiettivo

`OursDetector` (`src/ralmon/eval/ours.py`) still builds the hierarchical `RuleAttributor`, so no detector produces `Alert.p_kappa` or `Alert.cause_set` and the runner path of WS08-T09 is tested only with scripted stubs. Wire the proposed method of ADR-074: (1) `ours` builds the `LikelihoodRule` of WS05-T12 from `configs/attribution_likelihood.yaml` and the run option `sensitivity_values` (labelled sensitivity values; an `awaiting_human_value` row without a supplied value fails loudly) and exposes `alert_inputs(patient_id, alert)` (built with `alert_inputs_from_rule`) and `likelihood_rule`, keeping the evidence vectors it needs; (2) `ours-hier` is the same detector with the hierarchical rule (unchanged behaviour, `p_kappa` and `cause_set` None); (3) the `set_selector` of `RuleAttributor` is built from a `SubtypeSetCalibrator` fitted on the calibration part (patient-level split of the builder), with a separate instance for the confounder pairs; before a calibrator is fitted the selector is `cumulative_level_set` with the declared level; (4) the A4 variant (`ours-A4`): the witness cells removed and the robot-derived system fields `None` through the existing A4 mask; (5) the device profile of the run (`driver_with_diagnostics` / `without_diagnostics`, cuff resolution) reaches the extractor through `device_capabilities_from_manifest`; (6) `run_options.attribution` examples in `experiments/` configs (`loose_after_ms`, `set_alphas`, `pair_primary_templates`, `twins: separate`) as labelled test values for a smoke run, never as headline values.

**What was built.**
- `ralmon.eval.ours`: `LikelihoodSpec` (table path, `sensitivity_values`, `diagnostics_profile`, `grouped_variant`, `set_alpha`, `set_mode`, `min_cell_size`); `OursDetector(..., likelihood=None, a4=False)`. Without `likelihood` it is `ours-hier` exactly as before (`p_kappa`, `cause_set` None; `alert_inputs` and `likelihood_rule` are None, so the runner's optional hooks do not apply). With it: the `LikelihoodRule` is built at construction with `needs_cumulative_level=False` (an awaiting row without a supplied value raises `AwaitingValueError` there), `run` uses `RuleAttributor(..., rule, set_selector=self._select)`, and the detector keeps, per VIOLATED alert, the verdict record, the evidence vector the rule read and the hierarchical rule's kappa (computed by a second `RuleAttributor` on the same records and evidence) for `alert_inputs(patient_id, alert)` (built with `alert_inputs_from_rule`). A cascade effect points to its root's entry (it carries the root's posterior). Entries are keyed `(patient, instance_key, t_ms)` because plan instance keys can repeat across days; `fit` and `at_alpha` give each detector its own store. `OursRunDetails.evidence` (new last field, default empty) exposes the vectors of the last run.
- Sets: `_select` is the injected selector. With a fitted `SubtypeSetCalibrator` for the population in use it returns `predict_set(..., model_version=rule.model_version).subtypes`; otherwise `cumulative_level_set` with the declared `cumulative_level` (counted as `cumulative_fallback`). `fit_set_calibrator(alerts, *, test_patient_ids, population)`, `install_set_calibrator` (refuses a stale token with `StaleSetCalibratorError`), `set_calibrator`, `using_population("pairs")` (a SEPARATE instance; a population without its own calibrator never borrows `main`), `set_selector_metadata()` (mode, `set_alpha` as a string, fallback level labelled "sensitivity, not a proposal", per population the calibration size, thresholds with `inf` written as null plus the `fallback` flag, the `guarantee` and `assumptions` strings copied as the set builder states them, and the sets issued per population and template with `full_set_fallback`, `top1_fill`, `cumulative_fallback`).
- A4: `a4=True` passes `exclude_robot=True` to `extract_evidence` (witness, `battery_low`, `nav_task_failed`, `manip_task_failed` None; the four aggregates recomputed over the devices) and builds the rule with `a4=True` (the cells of `masks.a4.cells_removed` are dropped; `delta` is then not needed). Runner name `ours-A4`.
- Runner: `build_detector` handles `ours`, `ours-hier` (hierarchical, even if a `likelihood` block is present) and `ours-A4` itself; any other `ours-*` still goes to the extension modules and gets the likelihood block if configured. `detector_params.ours.likelihood` is the configuration (keys `sensitivity_values` (required), `diagnostics_profile`, `grouped_variant`, `set_alpha`, `set_mode`, `min_cell_size`); the table is always `<repo>/configs/attribution_likelihood.yaml`. `make_environment(..., manifest=)` completes the declared `device_profile` with `device_capabilities_from_manifest` when the manifest records `settings.device_profile` (cuff resolution, content sensing, authenticating devices, diagnostics nodes) and exposes the manifest's `diagnostics_profile` (`DetectorEnvironment.diagnostics_profile`); a declared profile that disagrees is a `ConfigError`. Before the test run the runner runs a detector with `fit_set_calibrator` and `set_alpha` on the calibration patients, labels the alerts (TIGHT, the scoring side reads the truth), fits and installs the main-population calibrator (`attribution_report.calibrate_detector_sets`), and reuses those records for the equal-coverage block. `meta.attribution.set_selector.<det>` has the metadata above plus `calibration` (alerts, patients, `fitted`, or the reason it stayed cumulative). `ralmon.conformal` now also exports `cumulative_level_set`, `StaleSetCalibratorError`, `PatientLeakError`, and `ralmon.attribution` exports `LikelihoodConfigError`, all outside `__all__` (the layering test requires the package root).

**Judgment calls.**
1. **Trigger of the likelihood rule.** `ours` uses it only when `detector_params.ours.likelihood` exists; without the block it stays hierarchical, so every configuration written before ADR-074 (and the 6837 earlier tests) runs unchanged. The task text ("`ours` builds the LikelihoodRule ...") is met for every configuration that supplies the block; a headline `experiments/main.yaml` must supply it. `ours-hier` ignores the block. Tell me if `ours` without the block should instead fail.
2. **Where `sensitivity_values` live.** `run_options.detector_params.ours.likelihood.sensitivity_values` (the task says "run option `sensitivity_values`"; `run_options.attribution` is the scoring configuration and the parser of WS08-T09 refuses unknown keys there). `cumulative_level` is also required in it (the declared level of the pre-fit selector); it is outside the model-version token, as the rule defines it, and is recorded by the detector, not by `rule.metadata`.
3. **Calibration part and the true subtype.** The detector never sees the truth, so the calibrator is fitted by the runner (scoring side) from the labelled alerts of the calibration patients; labelling TIGHT, posterior `lik`. It is fitted once per detector name and shared with the `at_alpha` siblings (the posterior does not depend on the monitor level). The detector is run on the calibration patients before the test run; the calibration records are cached and reused by the equal-coverage block (running the calibrated detector on a calibration patient would raise `PatientLeakError`, by design).
4. **Calibration part is fitted for the main population only.** The pairs have their separate calibrator API (`population="pairs"`, `using_population`), tested, but the runner does not yet fit it from the pair calibration part: the pair report (`attribution_equal_coverage.<det>.pairs`) still calibrates its own `SubtypeSetCalibrator` on posteriors as in WS08-T09, and the `Alert.cause_set` of a pair member comes from the main calibrator (the transfer). The pair metrics never read `cause_set`.
5. **`ours-A4` is the full A4 of EC-OP-5 (extractor run without the robot + rule cells removed), on the same verdict records.** The verdicts are not recomputed without the robot (the INT instance with `no_witness` stays violated), as documented in `evidence-channels.md`; WS08-T04 states which implementation it reports. WS08-T04 may supersede the builtin by a `variant_components("ours-A4")` of an extension module only if it renames it (the builtin wins).
6. **Hierarchical kappa for `hier`** comes from the hierarchical rule on the same records and (for A4, masked) evidence, with its own cascade links; an effect alert uses its root's.
7. **Mini fixture.** The one fixture pair lands in the train part under the smoke split (0.34/0.33/0.33), so the fixture config uses `0.3/0.3/0.4` (6 patients 2/2/2; the pair in test). Even so the pair has `lambda_a = lambda_b = 0` (the mini days carry almost no evidence) and no calibration pair, so the pair set calibration is `no calibration or no test pair with a matched alert`. The mini run is a plumbing check: tight log score from one alert (log 3), set size 10 (the full set), calibration sets with 2 calibration alerts.

**Known limits.** Pair calibrator not fitted by the runner (4). `family` and `cell_scope` of the sensitivity design still not implemented in `LikelihoodRule`. Detector memory: the record and vector of every VIOLATED alert are kept until `fit` (fine for the benchmark scale; reconsider if a run keeps millions of alerts). The per-day `OursRunDetails.evidence` is the last run only.
