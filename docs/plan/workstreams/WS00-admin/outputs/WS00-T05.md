## ROS 2 distribution and Gazebo compatibility

Humble:
- TIAGo: `pal-robotics/tiago_simulation` branch `humble-devel` (default), released in rosdistro Humble as `tiago_simulation 4.13.0-1`, latest release "4.13.0 (2026-08-24)". `tiago_gazebo` depends on `gazebo_ros` and `gazebo_ros2_control` (Gazebo Classic) and also on `gz_ros2_control`, `ros_gz_bridge`, `gz-sensors6` (new Gazebo, "Add support for new gazebo" in 4.10.0, 2026-01-12). PAL's launch default on Humble is Classic: `default_value='classic' if environ.get('ROS_DISTRO') == 'humble' else 'gazebo'`. `gz-sensors6` belongs to the Fortress collection (inference of the research agent: the new-Gazebo option on Humble is Fortress, not Harmonic; PAL does not say so). Nav2 is included (`navigation:=True`; `tiago_2dnav` depends on `pmb2_2dnav`, which depends on the Nav2 packages).
  Source: https://api.github.com/repos/pal-robotics/tiago_simulation/branches, https://raw.githubusercontent.com/pal-robotics/tiago_simulation/humble-devel/tiago_gazebo/CHANGELOG.rst, https://raw.githubusercontent.com/pal-robotics/tiago_simulation/humble-devel/tiago_gazebo/package.xml, https://raw.githubusercontent.com/pal-robotics/launch_pal/master/launch_pal/robot_arguments/common.py, https://raw.githubusercontent.com/gazebo-tooling/gazebodistro/master/collection-fortress.yaml, https://index.ros.org/p/pmb2_2dnav/, consulted 2026-10-08.
- Nav2 `1.1.20-1` and ros2_tracing `4.1.2-1` are released for Humble. On Humble ros2_tracing "will not work out-of-the-box": LTTng must be installed and, with binaries, `tracetools` cloned and built. Source: rosdistro `humble/distribution.yaml`; https://raw.githubusercontent.com/ros2/ros2_tracing/humble/README.md, consulted 2026-10-08.
- Python: Humble targets Ubuntu 22.04, Python "3.10.4" (REP 2000); the Ubuntu 22.04 default is "python3 (3.10.6-1~22.04…)". Source: https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-2000.rst and https://packages.ubuntu.com/jammy/python3, consulted 2026-10-08.

## ADR-011 decision

- **Superseded: ROS 2 Humble with Gazebo Classic** (decision of gab, 2026-10-08, recorded as the superseding ADR named in `03-decisions.md`). Gazebo Fortress through PAL's new-Gazebo option is the fallback if Classic blocks a needed feature.
- Evidence: PAL supports the TIAGo and TIAGo Pro simulations only on Humble (no Jazzy branch, maintainer statement), and its Humble default is Gazebo Classic; the real robots run Humble and mixing nodes of different distributions is not supported (Open Robotics on Discourse: "NOT MIX NODES BETWEEN ROS DISTROS", https://discourse.openrobotics.org/t/incompatability-between-distributions/43747; ROS docs: "the same ROS version and the same RMW implementation", consulted 2026-10-08); the AWS hospital world runs on Humble with Classic without porting; Nav2 and ros2_tracing exist for Humble (tracing needs LTTng and a source build of `tracetools`).
- Python: Humble delivers Python 3.10, which does **not** satisfy ADR-016 (3.11 or newer) while the ROS 2 wrappers import `ralmon`. ADR-016 is therefore reopened and superseded in the same decision: the floor of `ralmon` becomes Python 3.10 (a search of `src/ralmon` on 2026-10-08 found no 3.11-only feature: no `Self`, `StrEnum`, `tomllib`, `ExceptionGroup`, `datetime.UTC`, `Never`, `assert_never`; the migration and a test run under 3.10 belong to WS07-T01).
- Lifecycle nodes (`rclpy/lifecycle` on the `humble` branch) and the QoS deadline and liveliness policies with their events ("Offered deadline missed", "Liveliness lost") exist in Humble. Source: https://github.com/ros2/rclpy/tree/humble/rclpy/rclpy/lifecycle and https://raw.githubusercontent.com/ros2/ros2_documentation/jazzy/source/Concepts/Intermediate/About-Quality-of-Service-Settings.rst (same text in Humble), consulted 2026-10-08.
- The `ralmon` core stays ROS-independent; the existing image `ralmon-ros2:jazzy` (ADR-031) is replaced by a Humble image in WS07-T01.
