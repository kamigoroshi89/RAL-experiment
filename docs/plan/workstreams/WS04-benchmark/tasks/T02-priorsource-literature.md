## Obiettivo

Implement the `PriorSource` contract (`ParamProvenance`, `PatientParams`, `AdherenceParams`, `DeviceErrorModel`, `PriorSource`) and `LiteraturePriorSource`, the only prior source available until credentialing is granted (ADR-005). Every parameter carries a `source_ref`; a value without one makes the constructor fail, and a parameter for which no human has supplied a value stays `awaiting_human_value` and is never filled by the agent. Concrete output: `src/ralmon/benchmark/priors.py`, the parameter file `configs/priors/literature_hypertension.yaml`, and the generated **parameter-provenance table** `docs/benchmark/parameter-provenance.md` that a human verifies (H1 of the workstream README). This closes R3-W3 for the generator: parameters are anchored in a named source, not asserted.

## Test

All fixture values are arithmetic, live only in tests, and the fixture-only files carry `fixture_only: true`. Write and run these first.

1. `test_dataclass_shapes_match_contract`: field names and order of the four dataclasses equal the contract (hand-copied), and `PriorSource` has `name`, `sample_patient`, `adherence`, `device_errors`, `provenance`.
2. `test_missing_source_ref_fails_constructor`: a YAML row with a value and an empty `source_ref` raises `MissingProvenanceError` naming the parameter.
3. `test_every_contract_field_has_provenance_entry`: `provenance()` covers every numeric field of the four dataclasses (introspected with `dataclasses.fields`), one `ParamProvenance` each, and returns them in a stable order.
4. `test_unfilled_parameter_raises_on_use`: a row with `value: null` and `status: awaiting_human_value` loads with `strict=False` and `unfilled_names()` lists it; `sample_patient` then raises `UnfilledParameterError` listing all such names; `strict=True` raises at construction.
5. `test_unverified_names_reported`: with `verified_by` null on two rows, `unverified_names()` returns exactly those two, sorted; with all set it is empty.
6. `test_fixture_only_prior_rejected_by_default`: a file with `fixture_only: true` raises `FixtureOnlyPriorError` unless `allow_fixture_only=True`; the prior's `name` then ends with `-FIXTURE-ONLY` and every `source_ref` starts with `FIXTURE-ONLY`.
7. `test_sample_patient_deterministic_given_generator`: the same `numpy.random.Generator` seed and `patient_index` give identical `PatientParams`; `patient_id` is a pure function of `patient_index` (format `p` plus a zero-padded index).
8. `test_sample_patient_respects_truncation`: with a fixture distribution truncated to `[lo, hi]`, 1000 draws lie inside; Hypothesis over random `lo < hi` holds.
9. `test_distribution_family_allow_list`: only `constant`, `uniform`, `normal`, `lognormal` (each optionally truncated) load; another family raises `PriorConfigError`; parameters of every family are validated (SD non-negative, `lo < hi`).
10. `test_probability_fields_validated`: `p_delay`, `p_omission`, `p_double_take`, `dispenser_bounce_prob` outside [0, 1], or a sum of the first three above 1, raise `PriorConfigError`.
11. `test_ar_reference_step_required`: the `ar_noise_phi` row must carry `reference_step_ms`; without it `PriorConfigError` (the coefficient is meaningless without its sampling step; T03 rescales); `LiteraturePriorSource.reference_step_ms('ar_noise_phi')` returns it.
12. `test_provenance_table_is_deterministic_and_complete`: the rendered table has one row per parameter row of the YAML files given, columns `parameter`, `field`, `unit`, `value or distribution`, `source_ref`, `source_type`, `verified_by`, `status`, `consumer task`, `note`; rendering twice gives identical text; `--check-table` fails when the committed table differs from the YAML.
13. `test_committed_provenance_table_is_current`: `python -m ralmon.benchmark.priors --check-table` exits 0 on the repository files.
14. `test_no_parameter_literals_in_generator_modules`: parse every module under `src/ralmon/benchmark/`; any float literal other than 0.0 and 1.0, or integer literal other than 0, 1, 2 and -1, is reported unless its line ends with `# algorithmic: <reason>`. Numbers must come from YAML.
15. `test_protocol_swappable`: a stub class implementing the four `PriorSource` members is accepted by a function typed against `PriorSource` (mypy-checked in the same run).

## Passi

1. Write `tests/benchmark/conftest.py` (fixture-only prior file builder) and `tests/benchmark/test_priorsource.py`. Run `pytest tests/benchmark/test_priorsource.py -q`, confirm failure, commit `WS04-T02: add failing priorsource tests`.
2. Implement the contract types verbatim from `02-interfaces.md#priorsource`, the exceptions (`MissingProvenanceError`, `UnfilledParameterError`, `FixtureOnlyPriorError`, `PriorConfigError`) and the YAML loader. Row schema: `value` or `dist` (family plus parameters, optional truncation), `unit`, `source_ref`, `source_type` (one of `published_literature`, `standard`, `public_dataset`, `design_choice`, `declared_assumption`, `illustrative_unverified`, `fixture_only`), `verified_by`, `status` (`filled` or `awaiting_human_value`), `note`.
3. Build the **needs matrix** in the YAML and in the table: one row for every field of `PatientParams`, `AdherenceParams`, `DeviceErrorModel`, each with `consumer task` (T03 pressure, T04 PK/PD, T05 adherence, T06 device errors and T07 faults). Rows: `baseline_sbp_mmhg`, `circadian_amplitude_mmhg`, `ar_noise_sd_mmhg`, `ar_noise_phi` (with `reference_step_ms`), `emax_mmhg`, `ec50`, `absorption_rate_per_h`, `elimination_rate_per_h`, `onset_delay_range` (lower and upper), `p_delay`, `p_omission`, `p_double_take`, `mean_delay_ms`, `cuff_error_sd_mmhg`, `cuff_bias_mmhg`, `dispenser_bounce_prob`, `ble_dropout_rate_per_h`.
4. Fill only what a source supplies. Values may be transcribed only from text that already exists in the repository with an explicit citation (a human-written extract under `docs/benchmark/source-extracts/`, or a passage of `docs/source/analisi.md`); transcribed rows get `status: filled`, `verified_by: null`. Everything else is `value: null`, `awaiting_human_value`. Standing notes written into the table: `cuff_error_sd_mmhg` and `cuff_bias_mmhg` cite ISO 81060-2 with edition and clause to be confirmed by the human, and the note states that the standard gives acceptance limits for a device under validation, not the error of a particular device, so the human must declare whether the benchmark uses the limits as a conservative device model or a typical performance from a validation study (declared in `rationale`); `adherence` rows are `declared_assumption` (analisi §5.1: no public smart-dispenser dataset); PK/PD rows carry the drug anchor of the registry (`rationale` copied from the registry entry; if the registry says "illustrative, unverified" these rows do too) and no agent names a drug.
5. Compare the needs of T03 to T09 with the contract fields and list every gap: the reference sampling step of the autoregressive coefficient, circadian phase, heart-rate and SpO2 level parameters, pulse-rate error, nominal cuff inflation duration and its variability, dose normalisation convention, adherence persistence, double-take gap. Append one ADR (status `proposed`) listing the gaps, proposing that `PriorSource` gain the missing fields in a new contract version, with old version, new version, affected tasks (T03 to T09, T13) and migration; do not edit `02-interfaces.md`. Until that ADR is accepted, the task that introduces each gap parameter adds it as a row (same schema, `status: awaiting_human_value`) to `configs/benchmark/generator_design.yaml`, created by WS04-T03; the loader and the table renderer of this task already accept that file and its sibling configs when present.
6. Implement `LiteraturePriorSource`, the renderer and the entry point `python -m ralmon.benchmark.priors --write-table | --check-table` (writes only the region between the `BEGIN GENERATED` and `END GENERATED` markers of `docs/benchmark/parameter-provenance.md`). Write the hand-written header of that file once: purpose, the verification procedure for a human (open the source, confirm value, unit, population and reference step, set `verified_by` in the YAML, regenerate), and the meaning of each `source_type` and `status`.
7. Refactor, run `ruff check src tests`, `mypy src/ralmon`, `pytest tests/benchmark -q`; commit `WS04-T02: add PriorSource, LiteraturePriorSource and provenance table`; set `status: done`.
