It closes review item R2-W8 ("a multivariate time-series learner ... is in fact residual-based anomaly detection") by making that reading an explicit, measurable comparison. Concrete output: `src/ralmon/baselines/b2_anomaly_detection.py`, `b2_features.py` and their tests.

## Notes

**Hand-over from WS05-T05 (forecaster, ADR-057).** The index of a `Forecast` path is `(t - t_from_ms) // step_ms - 1` (`mean[k]` predicts `t_from_ms + (k + 1) * step_ms`), not `floor((t - t_from_ms) / step_ms)` as the test text above writes it. The Protocol call `predict(history, t_ms, horizon_ms)` has no target signal: a baseline that needs a given signal must call the concrete class with the keyword `signal=` (or pass a history that holds one signal only). `supported_signals` and `model_version` exist on every forecaster; import the classes and `InsufficientHistoryError` from `ralmon.monitor`, which now lists them in the public API table.

### Hand-over (worker, 2026-10-10, from WS06-T05: what B2 must mirror for WS06-T07 test 11)

B4 is implemented (`src/ralmon/baselines/b4_conformal_only.py`) and WS06-T07 test 11 requires the residual series of B2 and B4 to be equal. B4's rule: the forecast is issued at the device time `t_prev` of the previous delivered sample of the signal with horizon `t - t_prev` and read at index `(t - t_prev) // step_ms - 1` (not the `floor` form of the test text above). The first sample of a signal has no residual. A gap shorter than one step has an empty forecast path and gives no residual (counted as `no_forecast`). `InsufficientHistoryError` from the forecaster skips the residual and counts it. A duplicate (a sample whose device time is not later than the previous one) has gap 0 and no residual (`not_newer`), and does not replace the previous sample. A non-finite value is not a reading. The forecaster is called with the history of that signal delivered so far and the keyword `signal=` when it accepts it; a returned path that is not the one asked for is a `ValueError`. Lateness, pre-day samples and the history passed are as in B1 (see the Notes of WS06-T05). If B2 takes a conformal level, the allocated level comes from `BonferroniAllocation.per_test_exact` and `calibrated_for` must equal the forecaster `model_version`; B4 exposes the rows as `B4ConformalOnly.residuals`.

Which value WS08 uses is an experiment choice (a coarser step is faster and gives less dependent rows); no value is invented here. The detection time of a forest row is its grid time.
4. **Pooled calibration rows.** The isolation threshold is the `score_quantile` quantile of the scores of all calibration-day rows pooled. Rows of one day are strongly dependent, so `1 - score_quantile` is a row-level exceedance rate, not a per-day false-alarm probability, and no coverage statement is made for B2.
5. **Strictness.** A parameter that the mode does not use (`z_threshold` with `iforest`, `score_quantile` with `residual`) is a `ValueError` instead of being ignored; `score_quantile` is accepted on the closed interval [0, 1]; `z_threshold` must be a positive finite number (not a bool or a string). The forecaster is required for `residual` and `both` and may be `None` for `iforest` (it is then not fitted and not used; the signals are then not restricted to the supported ones).
6. **Scale.** At least two calibration residuals per signal are needed (fewer: no scale, B2 silent on that signal, named in `run_stats.uncalibrated_signals`; algorithmic constant, one value has no spread). A scale of 0 gives `z = 0` for a residual equal to the mean and `z = +-inf` otherwise, with the largest finite float as score. The scale is tied to `forecaster.model_version`; `run` raises `StaleCalibratorError` if it changed since `fit` (as B4 does for its calibrators).
7. **Lateness.** The lateness rule of the grid (B1, B3, B4, B5, the monitor) is applied to the monitored samples and the DISPENSE events that B2 uses (`late_inputs`, `late_events`); the task text does not mention it. A sample whose device time lies in `(t0 - step, t0]` is step 0 of the day; an earlier one is a delivered value without a residual row.

**What B2 sees and cannot see (also in the module docstring; the per-class lines are expectations derived from the design, not measurements).** Sees: a forecaster, the residual scale, samples of the monitored signals, DISPENSE events, the schedule of the plan. Reads no plan parameter, no registry, no evidence, no ground truth and no latent trace (`read_log` empty, `access_log` shows `observed` reads only on both splits, `denied` empty; ground truth of a training day is available to `fit` and is not read). Cannot see, by construction: the residual detector sees changes, not levels (a value held at 200 and a drift in steps under the scale never alarm), nor absences, nor events; it alarms on a wanted drop as on a rise. The forest has no band: pinned by `test_b2_iforest_blind_spot_it_has_no_band_a_level_shift_changes_nothing` (every blood-pressure value of the training days, the calibration days and the test day moved from about 120 to about 200 leaves the scores unchanged, because the splits of an isolation tree are uniform between the minimum and the maximum of a feature). Honest observation from a first attempt at a different test: with a training population around 200, test levels of 200 and 120 gave mean forest scores of 0.521 and 0.511, that is, an out-of-population level in one blood-pressure feature among thirteen did not rank higher; the forest is a weak detector of a single out-of-range feature and strong only where the unusualness is spread over several features. Per template of the proposed method: RANGE only as an unusual value or a large change, never as a level against a band; HOLD, COUNT, SCHED, RESP, SYS and INT only as unusual feature values, if at all. WS08 must report B2 per class and per subtype and must not read its recall on C2/C3 as a statement about forecasting or conformal prediction.

**Statement of the guarantee.** None. B2 has no coverage statement: the z-threshold is an operating parameter of a normal-theory rule applied to residuals that are not normal, and the forest threshold is an empirical quantile of dependent rows.

**Three sentences for the paper's baseline paragraph (step 7).** B2 is the anomaly-detection baseline: a z-score of the residual of a one-step forecast of each continuous signal, with the residual mean and spread estimated on calibration days, and an Isolation Forest on features of the observed trace (last values and their age, the 24 h dispense count, the time since and to the scheduled ticks, the time of day), both unsupervised. It uses the same forecaster class and the same training and calibration days as the proposed method, so a difference to the proposed method is not due to the forecasting model. It has no access to the clinical bands, windows or templates and makes no attribution, so it measures how unusual a reading is and not whether it violates a care plan, which is the reading of the proposal that review item R2-W8 asks the paper to distinguish from.
